# Folivyn 验证与实施计划

英文/简体中文实现与 27 项测试结果见[本地化验证记录](localization-validation.md)，本轮修复与真实窗口验收状态见[原生验收记录](native-validation.md)。

日期：2026-10-26。本文的启动、输入延迟和内存数值均为**待验证的设计目标**。小型 P0 已实现并编译，27 项自动测试在常规和禁网环境均通过；Folivyn 国际化 arm64 Release 构建文件总大小 264.09 KiB、磁盘占用 292 KiB，低于 15 MiB 预算。真实窗口交互及性能尚待验收，详见[本地化验证记录](localization-validation.md)及[原型验证记录](prototype-validation.zh-CN.md)。下文区分本次原型验收和后续完整 V1 验收。

本机基准信息已实际读取：Apple M4、16 GiB 内存、macOS 26.5.1、arm64；Xcode 26.6，Apple Swift 6.3.3。全局 developer directory 指向 Command Line Tools，需要时可以命令级指定 `/Applications/Xcode.app/Contents/Developer`，本轮未修改系统配置。

**1. P0 保持小范围，先验证文本编辑闭环**

| 原型任务 | 交付 | 决策门槛 |
| --- | --- | --- |
| 原生文本 | Swift/AppKit 与系统文本组件，基础输入、选择、打开、保存、另存和撤销 | 中文/Emoji/组合字符稳定；普通保存不擅自格式化，失败保留内容和 dirty |
| 多文件 tab | 同窗切换多个文件，各自拥有选区、滚动、dirty 与 undo | 重复打开定位到已有 tab，切换/关闭/保存不影响另一文档；关闭 dirty 文件有提示 |
| Reload 与外部修改 | 手动从磁盘重读；激活检查和保存前核验 | 覆盖取消、放弃后重载、另存副本后重载；读入或副本保存失败保留本地内容；成功后清旧 undo、尽量保留视图位置 |
| 基础着色 | Python、Java、JavaScript/TypeScript、JSON/JSONC、Shell 的简单本地着色 | 不改文本、不污染 undo；超预算退到纯文本，不宣称完整语法解析 |
| 完全离线 | 无账号、网络服务、语法下载、遥测或自动更新 | 断网后从首次启动到所有 P0 功能均可用，打包资源齐全；没有远程包依赖 |
| 安装体积 | arm64 Release 应用包 | `.app` 初始目标 ≤15 MiB，记录实际字节数、架构及构建配置；开发工具/缓存另计 |

P0 不含 CSV 表格、JSON 树、Quick Look、恢复草稿、持续文件监听或日志 tail；CSV/JSON 可先按文本打开。这些功能仍在完整 V1 计划中，后续逐项完成闭环验收，不能因原型缩小而从产品范围中删除。P0 先用系统能力着色，不引入 tree-sitter 或其他远程依赖。

Reload 的“保留视图位置”允许因文件缩短而夹紧选区/滚动位置；重载后 Cmd-Z 不能恢复外部更改前的旧内容。无本地修改的外部重载和有本地修改的冲突流程分别测试；磁盘文件删除、无权限、无效编码及另存取消都不得清空当前内容。保存前核验不等于消除了所有并发写入竞态，V1 再验证更完整的协调策略。

离线测试先用本地文件执行全部场景，结合依赖清单与网络请求观测。发布者的 Apple 签名/公证、开发阶段未来可能的依赖获取不属于应用运行功能；不能把首次启动下载、联网激活或在线语法服务列为使用前提。

先给系统文本栈约 5 个工作日的核心验证窗口。若存在输入法/撤销/数据正确性阻塞，或正常文件性能经过一次有界优化仍不达标，用相同语料评估 Scintilla Cocoa。根据结果选定一套可写引擎；不同时长期维护两个实现。引擎切换可能增加 1–2 周，须重新评估排期。

**2. 不可妥协的数据验收**

以下为完整 V1 门槛；其中输入、tab、保存、Reload、冲突与离线要求适用于 P0，结构视图、恢复与 Quick Look 随对应阶段实施验收。

- 未修改的文件经打开、切视图、保存后逐字节一致；普通保存不自动格式化。
- CSV 改一个字段仅产生预期文本替换，未改字段及分隔符、引号、BOM、尾部换行保持原样；源文编辑和表格编辑交替后撤销/重做结果一致。
- JSON 的重复键、大整数、指数形式、转义词面和成员次序在查看时保持原样；非法 JSON 仍可用源码修复。
- 系统拼音组合、选词、删除、取消、焦点/标签切换、撤销重做不丢字或重复提交；候选框位置正确。覆盖中文、Emoji、组合音标、RTL 混排和 CRLF。
- 外部编辑、git checkout、原子替换、重命名、删除、保存失败和磁盘满均有确定行为；存在本地修改时不能静默覆盖另一版本。
- 连续切换三个以上文件后，各文档的 dirty、撤销、选区和滚动状态仍正确；重载只影响目标文档。读入成功前原文保持可恢复，失败不改变当前版本。
- 保存过程中进程终止后原文件与恢复数据可解释；恢复不会覆盖较新的磁盘文件。恢复点以已落盘 revision 为准，不承诺尚未持久化的最后按键。
- 异步解析/过滤返回过期版本时被丢弃，不能修改最新文本、选区或结构映射。
- 大文件/解析超预算时明确进入只读或降级状态；禁止只加载一部分却把它作为完整文件保存。

**3. 第一轮性能目标**

统一使用 Release 构建、同一字体/主题和同一组本地 SSD 语料。计时包括请求打开、窗口呈现、内容可见、编辑可用、语法就绪和结构就绪，不以“进程已启动”代替“文件已可用”。

| 场景 | 初始目标与阶段 |
| --- | --- |
| 应用进程未运行，打开 1 MiB 常规源码 | 首次内容可见 P95 ≤ 800 ms，可编辑 P95 ≤ 1 s |
| 应用已运行，打开同类新文档 | 内容可见 P95 ≤ 200 ms |
| 10 MiB、约十万行、正常行长文本 | 输入到绘制 P95 ≤ 30 ms；记录超过 100 ms 的主线程阻塞并定位 |
| 5 MiB CSV / 1 MiB JSON（P2） | 专用视图首屏 ≤ 500 ms、完整解析目标 ≤ 2 s；同时源码可操作 |
| 空窗口稳定后 | physical memory footprint ≤ 100 MiB，空闲 CPU 持续接近基线 |
| 10 MiB 普通文本单页 | 主进程 footprint 目标 ≤ 250 MiB，另报峰值和解析快照成本 |
| 100 MiB 日志的只读降级路径（V1） | 先读有界前缀，首屏目标 ≤ 1 s，可取消；不承诺全文件高亮 |
| arm64 Release `.app`（P0） | 安装后应用包 ≤15 MiB；报告逻辑大小和磁盘占用，不以压缩包大小替代 |

以上均是初始预算，不作为市场宣传。原型优先完成正确性、离线和体积核验，再报告已实际测量的性能项目；未执行的 P95 测试保留“待验证”，不将一次启动结果当作验收。CPU 以固定时窗与活动记录判定，不用一次瞬时采样；Quick Look 进程和可选子进程的资源单独报告。主进程内存不混用 RSS、虚拟内存和 physical footprint。

每个常规启动场景至少运行 30 次，记录 P50/P95、最大值、系统负载、缓存状态和样本哈希。区分“进程冷启动、文件系统缓存热”和“重启后的首次启动”；不能把前者冒充磁盘冷启动。Finder 端到端耗时用自动化时间戳/录像等外部观测，应用内部用 signpost/Instruments 分段。下载后首次 Gatekeeper 检查单独记录，不混入常规启动统计。

**4. 语料与分级能力**

| 语料组 | 至少覆盖 |
| --- | --- |
| 普通源码 | 100 KiB、1 MiB、10 MiB；Python、Java、JS/TS、Swift、C/C++ 等代表性文件 |
| 文件形状 | 大量短行、1 MiB 单行 JSON、10 MiB 单行文本、100 MiB 日志、无尾部换行 |
| Unicode/编码 | UTF-8 BOM/无 BOM、UTF-16 LE/BE、GBK/GB18030 验证样本、非法序列、中文/Emoji/组合字形、混合换行 |
| CSV | 引号内逗号/换行/双引号、空/缺失/末尾字段、表头重复、00123、长账号、日期样式、公式样式文本、巨大行数与列数 |
| JSON | 重复键、超过安全整数范围的数、指数、转义、未完成输入、深嵌套、超大数组、JSONC/JSON5 的明确降级 |
| 文件系统 | 本地、只读、符号/硬链接、外部原子替换、网络/云盘按可用环境补测，权限与扩展属性 |

V1 初始策略可把 ≤10 MiB 作为完整编辑/解析的性能基准，10–50 MiB 作为限额编辑评估区间，更大文件优先只读预览；这是实验分档，不是 P0 或最终版本已支持的上限。P0 可先设置更保守的大小限制并清楚提示。长行、节点数、列数与嵌套深度可能比文件大小更早触发降级。

普通只读预览先按有界前缀显示，并明确标注未展示全部内容；完整滚动/搜索大日志需要稀疏行索引和流式扫描，是单独交付项。不能把 mmap 或“虚拟化表格”当成自动解决内存、索引与解析成本。

**5. 测试组织**

纯 Swift/FileCore 单元测试覆盖识别、编码、文本事务、CSV 扫描和局部编辑、JSON 范围与词面；属性/随机测试覆盖范围边界与字段转义。对固定语料比较变更区间和文件字节哈希，避免只比较解析后值。

P0 优先测试文件往返、重载与冲突等可能损坏数据的逻辑，并实际操作多 tab、输入、撤销和本地着色；不为纯界面样式写镜像测试。AppKit 集成测试覆盖 undo、dirty、文档切换、保存失败与外部事件；V1 再使用 XCUITest/实际键盘操作覆盖 Finder、中文输入、VoiceOver、拖放与扩展。最低支持系统需要独立环境测试，不能只在开发机 macOS 26 上编译一次就宣称 macOS 14 已通过。

支持 Intel/Universal 需要所有依赖架构与实际运行测试；首版默认优先 Apple Silicon。CI 先固定工具链，核心测试与应用构建分别运行，UI/输入法测试按可用 runner 和人工验收组合安排。

**6. 里程碑与粗略工作量**

以下按 1 名熟悉 Swift/AppKit 的全职开发者估算，包含持续测试，不含等待证书、商店审核或大规模引擎返工；AI 辅助不替代输入法、文件系统和设备验证。

| 阶段 | 时间估计 | 可验收结果 |
| --- | --- | --- |
| P0 小型原型（已实现，人工验收待完成） | 1–2 周验证窗口 | 打开/保存/另存、多文件 tab、Reload/冲突、基础着色；自动测试与体积已核验，补真实交互与性能验证 |
| P1 文本日用闭环 | 再 2–3 周 | 完善现有 tab/重载、常用高亮、查找替换、编码/换行、安全保存、冲突和草稿恢复 |
| P2 数据视图与 Finder | 再 2–3 周 | CSV 单字段局部修改和 JSON 源文映射原型通过后，交付专用视图、类型关联入口及 Quick Look |
| P3 测试版打磨 | 再 2–4 周 | 输入法与辅助功能回归、资源预算、支持系统测试、签名公证、DMG 和使用说明 |

第一版完整范围原估 **7–12 周**，这是条件化估计，P0 收窄不代表完整 V1 工程量减少；结构视图验证后移带来的风险需在 P1/P2 重新估算。可以先试用 P0/P1 文本功能，但只有 CSV/JSON 和 Finder 闭环完成后才算满足用户确认的 V1。若引擎切换、系统兼容或结构编辑正确性未过关，需要调整时间或明确缩小范围。

后续按用户反馈安排 Markdown/图片/PDF 预览、目录搜索、更完整 CSV 操作、JSON 结构编辑、多光标/折叠及可选语言服务；保持打开单个文件的启动与资源预算不退化。
